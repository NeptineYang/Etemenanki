## 1. 威胁模型

资产：用户源码、模型凭据、宿主机文件、模型调用额度、供应链完整性、报告可信度。

不可信输入：

1. 导入项目：源码、构建脚本、wrapper、Maven 扩展与插件、npm 生命周期脚本、Python 构建后端。
2. 第三方依赖与工具链下载物。
3. 模型输出：补丁、命令、文件路径、解释文本。
4. 用户配置中的私有仓库与镜像地址。

主要风险：构建脚本执行任意代码、路径穿越与符号链接逃逸、凭据泄露到模型请求或日志、依赖投毒、提示词注入诱导越权操作、沙箱逃逸。

## 2. 信任边界

| 区域 | 信任级别 | 约束 |
| --- | --- | --- |
| Windows 侧 Core / Tauri / CLI | 可信，但仍按最小权限运行 | 不监听端口，不读未授权路径，不接触凭据以外的系统资源 |
| Windows 侧 Java / Python Worker | 受控代码，处理不可信输入 | 只读源项目，不执行项目构建脚本，不联网下载可执行内容 |
| WSL2 发行版内 runner | 受控代码，处于不可信环境 | 非 root、cgroup 限额、仅工作区可写 |
| bubblewrap 沙箱内构建与测试 | 完全不可信 | 断网、只读根、独立 `/tmp`、禁止提权 |

模型输出、导入项目内容、依赖包内容一律按不可信处理。Worker 返回的结构化结果仍需按 schema 校验，越界值不得直接进入状态机。

## 3. 依赖获取：严格两阶段

### 3.1 第一阶段：联网下载

- 只允许经过 runner 内的白名单代理出网，默认放行 Maven Central、PyPI、npm 官方源与用户显式配置的私有仓库。
- 镜像可替换（阿里云 Maven、清华 PyPI、npmmirror 等），替换后自动加入白名单；锁定的依赖仍校验哈希。Maven 无锁文件，换源等于信任镜像运营方，报告必须注明。
- npm/pnpm 跳过安装脚本；Python 只安装 wheel。离线装不上的依赖写入报告。
- Maven 的扩展与插件无法禁用，按不可信代码处理，在同样受限的沙箱内执行。

### 3.2 已批准的例外：Gradle 源项目

Gradle 必须执行项目自身的构建脚本才能解析依赖，因此联网阶段允许执行脚本，条件是：

- 网络只开白名单，只允许下载类请求（代理仅放行 GET/HEAD）。
- 每个项目使用独立缓存，不与其它项目共享。
- 报告中注明“依赖阶段执行了项目脚本”。
- Gradle 仍属实验矩阵，不计入保证范围。

残余风险：项目脚本仍可经白名单域名外传数据。该风险在报告与文档中披露，不宣称已消除。

### 3.3 第二阶段：断网构建

- 所有构建与测试在 `--unshare-net` 的沙箱内执行，只使用第一阶段落盘的依赖。
- 缺少依赖时构建失败并输出缺口清单，不自动联网补齐。

### 3.4 Windows 侧只下载、不执行

没有 WSL2 时，类型分析所需的 JAR、wheel、npm 包在 Windows 侧只做下载与读取：

- Java 依赖用 Maven 官方解析库按 `pom.xml` 解析后下载，不执行插件与扩展。
- uv 与 pnpm 的锁文件已含每个包的地址与哈希，直接下载后解压读取，不安装、不运行脚本。
- 下载物解压前校验哈希；解压时限制条目数、单文件大小与总大小，拒绝绝对路径与 `..` 路径。
- 该下载与其它联网共用同一份白名单、镜像与代理设置。

### 3.5 Maven 解析一致性

- 以 Linux runner 的解析结果为权威：首次联网解析后写入 `deps.lock.json`，记录坐标、仓库、classifier 与 SHA256；WSL 构建与 Windows 分析都复用这份结果。
- 项目自带的 `<repositories>` 必须命中用户批准的白名单，未命中即阻断并要求显式确认。
- 版本范围与 `SNAPSHOT` 不进入保证路径：出现即按实验处理，报告中标注不可复现风险。
- 按操作系统激活的 profile 会造成 classifier 差异（如 native 包）：以 Linux 结果为准，Windows 侧缺失的 native 依赖记为缺口，不猜测替代品。

### 3.6 Gradle 约束

- wrapper 必须提供 `distributionSha256Sum`，且与官方发行版一致；缺失或不匹配即阻断。
- `distributionUrl` 指向非官方主机时阻断，用户可在设置中按项目显式放行，放行后按实验路径处理并在报告披露。
- 通过 `org.gradle.java.installations.auto-download=false` 禁用 foojay-resolver 的 JDK 自动下载，JDK 由环境包提供并固定版本。
- build scan 上传会被白名单阻断，报告中说明“构建扫描不可用”，不视为失败。
- 联网阶段只放行 GET/HEAD；项目脚本仍可能经白名单域名外传数据，该残余风险在报告与用户文档中披露。

### 3.7 无 WSL2 时的 Gradle

Windows 侧不执行脚本，因此无法解析 Gradle 依赖。Gradle 项目在缺少 WSL2 时只允许导入、扫描与查看依赖声明，不生成目标项目，报告给出“需安装 WSL2”的阻因。

## 4. 沙箱

- 专用 WSL2 发行版：关闭 automount 与 interop，`appendWindowsPath=false`，发行版内不存放用户凭据。
- runner 以非 root 运行，独占一个构建用户；该用户无权修改发行版基础文件。
- 构建与测试在 bubblewrap 命名空间内执行：只读根、独立 `/tmp`、`--unshare-net`、`--die-with-parent`、禁止获取新权限。
- 资源限制用 `systemd-run` + cgroup v2：CPU 配额、内存上限、进程数上限、磁盘配额与执行超时。
- 工作区位于发行版内 ext4；源项目经 `wsl.exe` stdio 以 tar 流单向传入，产物、补丁、日志与截图以 tar 流回传。
- 只有沙箱内产生的构建与测试结果可以作为自动验证证据。

残余风险：WSL2 与 Windows 共享内核，发行版隔离不等同于独立虚拟机；这一点在用户文档与安全说明中披露。

## 5. 文件与路径

- 源项目默认只读；所有写入发生在独立工作区。
- 路径校验覆盖：`..` 穿越、符号链接与 junction、Windows 保留名（`CON`、`NUL` 等）、长路径、大小写冲突、设备路径。
- 工作区根目录之外的读写请求一律拒绝，并记录审计事件。
- 归档解压（依赖包、环境包、用户上传）统一走同一套受限解压实现。

## 6. 模型边界与凭据

- API key：安装版存 Windows 凭据管理器；便携版用 DPAPI 加密文件，绑定当前用户账户。
- 云端模型按项目授权，记录范围、用途与有效期；未授权时只使用本地模型或确定性功能。
- 上传前做密钥与敏感信息扫描，只发送当前任务所需的最小片段与符号摘要。
- 日志记录 Provider、模型快照、请求目的与审计摘要；源码原文日志默认关闭。
- 提示词注入防护：导入项目中的注释、文档、测试数据一律视为数据而非指令；模型不得直接写宿主机、不得访问工作区外路径、不得调用未在白名单内的工具。
- 私有仓库凭据存 Windows 凭据管理器，按主机名索引；只在下载阶段由 runner 的代理进程读取并注入 `Authorization`，不进入构建沙箱、模型上下文、日志与报告。代理对凭据做主机绑定，转发到其他主机时剥除。

## 7. Tauri 2 安全基线

- 严格 CSP，只允许本地资源与受控的 `ipc:` 通信。
- capability 白名单：只开放实际使用的命令，默认拒绝。
- 禁止加载远程内容，外部链接交由系统浏览器打开。
- 发行版关闭 devtools。
- 每个 X.Y.0 的手工联调清单包含一次 Tauri 配置快照检查，确认上述四项未被放宽。

## 8. 审计

- 记录项目授权、模型快照、提示词版本、工具调用、补丁、测试证据与人工批准。
- 审计数据默认本地保存，支持按项目设置保留期限与删除。
- 安全扫描不能证明生成代码绝对安全，仍需人工审核与项目自身安全流程。

## 9. 残余风险披露

以下表述统一用于用户文档、安装说明与迁移报告，不得弱化：

1. WSL2 与 Windows 共享内核，发行版隔离不等同于独立虚拟机；沙箱降低攻击面，但不承诺绝对隔离。
2. Gradle 源项目在联网阶段会执行项目自身的构建脚本，脚本可能经白名单域名外传数据；白名单只限制目标，不保证数据不离开本机。
3. 使用第三方镜像时，依赖来源的信任转移给镜像运营方；Maven 没有锁文件可校验，报告会注明本次使用的源。
4. 沙箱与哈希校验降低但不消除供应链投毒风险；受支持范围外的框架与动态特性不在保证内。

## 10. 复核节点

安全策略在每个 `X.Y.0` 的 PR 合并前复核一次，复核项包括沙箱参数、白名单、凭据注入路径、Tauri 配置快照与上述披露文案。策略放宽必须走人工批准，不得随版本自动生效。
