# 语义差异与迁移保真

- 状态：V1 设计基线
- 日期：2026-11-17
- 依据：DESIGN.md §2、§3.3、§3.4，Q22、Q24、Q38、Q48、Q49
- 上位文档：[DESIGN.md](../../DESIGN.md)

## 1. 原则

默认目标是“行为不变”，不是“看起来像目标语言”。

1. 能证明差异不会出现时，生成目标语言的地道写法。
2. 证明不了时，生成保真实现（显式模拟源语言语义），并在报告中标注。
3. 保真实现必须可读、可替换：每个标注点给出源位置、差异原因与改成地道写法的条件，人工可逐处替换。
4. 禁止为了“代码好看”而静默丢弃语义。无法处理的构造进入缺口报告或人工任务。

“证明”指静态范围分析、常量传播、类型边界、调用点证据或差分测试，不指模型自信程度。

## 2. 语义差异清单

| 主题 | Java | Python | 默认策略 |
| --- | --- | --- | --- |
| 整数除法 | 向零截断 | `//` 向下取整 | 无法证明非负时生成截断实现并标注 |
| 取模符号 | 随被除数 | 随除数 | 按 Java 规则实现，标注 |
| 整数溢出 | 32/64 位回绕 | 任意精度 | 目标为 Python 时按需插入回绕；目标为 Java 时证明范围后可用原生类型 |
| 字符串长度 | UTF-16 码元 | Unicode 码点 | 依赖长度的逻辑按源语义实现（如 emoji 计数差异），标注 |
| 哈希容器顺序 | `HashMap`/`HashSet` 顺序未定义 | `dict` 保持插入序、`set` 无序 | 依赖顺序的代码显式改为有序容器，不假设一致 |
| 浮点格式化 | `Double.toString` 风格 | `repr` 风格 | 对外输出统一走显式格式化函数 |
| 十进制 | `BigDecimal`（scale + RoundingMode） | `Decimal`（context 精度） | 固定 scale 与舍入模式，标注差异 |
| 时间与时区 | `java.time`，`ZonedDateTime` | `zoneinfo`，naive/aware 区分 | 统一使用带时区类型，禁止 naive datetime 进入契约 |
| 正则 | `java.util.regex`，支持 `\p{L}`、占有量词 | `re`，命名组语法不同 | 复杂正则改写并加测试 |
| 空值 | `null` + 可空注解 | `None` | 保留可空性，不擅自改为空对象 |
| 相等性 | `equals`/`hashCode`，`==` 为引用比较 | `__eq__`/`__hash__`，`==` 为值比较 | 引用比较语义必须显式改写，不能直接映射为 `==` |
| 受检异常 | 编译期强制 | 无受检概念 | 保留异常类型与传播路径，不吞异常 |
| 并发 | 线程 + `synchronized` + `java.util.concurrent` | GIL + `threading`/`asyncio` | 共享可变状态改为显式锁或消息传递，标注风险 |

## 3. 编码与换行

- 读取源文件时优先使用构建配置声明的编码（Maven 的 `project.build.sourceEncoding`），未声明时再检测；处理 BOM 与 Python 的 PEP 263 声明。
- Java `.properties` 传统上按 ISO-8859-1 读取，需单独处理，不能统一按 UTF-8。
- 生成文件一律使用不带 BOM 的 UTF-8，并记录编码转换。
- 换行符沿用项目内占多数的风格；无法判断时使用 LF。
- 中文 Windows 上 javac 默认使用平台编码（GBK），构建命令必须显式指定编码，避免“本地能编译、沙箱失败”。

## 4. 类型证据与置信度

- 证据来源：显式注解与签名、调用点一致性、容器元素用法、测试运行观察、模型推断。
- 每条证据记录来源、位置与置信度。低置信度不得直接生成强类型，转为 `Any`/`Object` 并进入人工任务。
- 类型不确定项必须在报告中可检索，不能静默降级。
- 具体阈值与分级在 V1-A 基准后冻结（见待定事项）。

## 5. 契约保持

- JSON 字段命名：Jackson 默认 camelCase，Pydantic 默认 snake_case；生成时使用别名映射，保持原字段名不变。
- 日期与时间格式、`null` 的序列化方式、数字精度必须与源契约一致。
- 数据库：Spring 的物理命名策略会把 camelCase 映射为 snake_case 列名；Django 默认表名为 `app_model`。保持既有 schema 时必须显式设置 `db_table` 与 `db_column`。
- 对外 API 的状态码、错误结构与消息协议默认不变；变更需人工批准。

## 6. 支持范围与阻断

- Java 低于 17 或 Spring Boot 2 的项目：V1 直接阻断，输出缺口报告，支持计划记入 V2。
- 其余不在参考版本上的框架组合：走实验路径，结果单独统计，不计入“行为已验证率”。
- Java 反射、动态代理、自定义类加载器、字节码生成、JNI、复杂并发与自定义构建插件默认不保证；检测到即标记，不在静默状态下生成。
- Python `eval`/`exec`、动态模块加载、复杂元类、猴子补丁默认不保证。

## 7. Lombok 与注解处理器

- Java Worker 内置固定版本的 Lombok（MIT），分析前在独立副本中执行官方 delombok，把注解展开为普通代码。
- 项目使用的 Lombok 版本高于内置版本时，逐处标注可能的差异。
- MapStruct 等注解处理器的产物不在源码中，从 WSL2 基线构建生成的源码目录取回后再分析。
- 没有 WSL2 时只能分析到注解层，报告必须写明这一缺口。
