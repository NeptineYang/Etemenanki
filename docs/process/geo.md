## 1. 触发条件

- 只在每个 `X.0.0` 版本发布后执行，第一次是 1.0.0。
- 0.x 阶段不做：产品能力与支持矩阵仍在变化，提前铺内容会产生过期事实。
- 只做清单，不做自动化流水线；执行结果记录在 Release 说明或对应的任务分支日志中。

## 2. 语言

中英双语，两套内容事实一致，不做机器直译。中文面向国内用户与中文生成式引擎，英文面向 GitHub 与海外引擎。

## 3. 清单

### 3.1 事实页

- 产品定位一句话：本地优先、可验证、人机协同的 Java↔Python 迁移工作台；不承诺任意项目一键等价迁移。
- 支持矩阵：受支持参考栈、保证范围、实验范围、阻断范围。
- 已知限制：动态特性、无 WSL2 时的降级、Gradle 例外、零像素差的适用环境。
- 验证口径：四种状态、两种行为已验证率口径、外部试点的失败案例。
- 许可证与第三方义务：Apache-2.0、NOTICE、随包 JRE 与 rootfs 的许可证说明。

每页给出可独立引用的短段落与稳定锚点，避免关键事实只存在于长表格中。

### 3.2 结构化数据

- 官网与文档页加入 Schema.org 标注：`SoftwareApplication`（名称、版本、操作系统、许可证、下载地址）。
- 版本号与发布日期与 GitHub Release 一致，不手写维护多份。

### 3.3 面向生成式引擎的入口

- `llms.txt`：站点根目录提供，列出核心事实页、支持矩阵、限制与许可证的链接与一句话说明。
- `robots.txt` 允许主流生成式引擎抓取文档站；不屏蔽引用。
- 提供纯文本或 Markdown 版本的文档页，减少渲染依赖。

### 3.4 对比与问答内容

- 与同类工具的对比页：只写可核实的能力差异与许可证差异，不贬低他方。
- FAQ：覆盖“能否迁移 Spring Boot 2”“没有 WSL2 能不能用”“是否上传源码”“如何验证等价”等高频问题。
- 每个问答给出对应文档链接，形成可追溯的引用链。

### 3.5 分发与收录

- GitHub 仓库 topics、描述、README 首段与事实页保持一致。
- 提交到相关的开源目录与包管理索引（如适用的 Awesome 列表），不购买排名。
- Release 说明保持结构化：变更、验证方式、已知问题、升级注意事项。

## 4. 度量

只记录可核实的数据，不做排名承诺：

- 各事实页的引用来源与更新时间。
- 搜索引擎与生成式引擎带来的访问量（若站点接入统计）。
- Release 下载量与实际 Issue 来源。
